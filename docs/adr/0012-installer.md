# ADR-0012: 설치 프로그램은 Inno Setup으로 만든 EXE 하나다

- 상태: 채택
- 날짜: 2026-09-04
- 관련 문서: `docs/DEVELOPMENT_MASTER_PLAN.md` 9절(Phase 9), 16절 · ADR-0011 · `AGENTS.md` 3절
- 해소 대상: 마스터 계획 9절 Phase 9의 "Setup EXE 또는 MSI", "설치·업데이트·제거 테스트", "WebView2 Evergreen 우선"

## 맥락

ADR-0011이 설치 폴더의 배치를 정했고 `pnpm shell:publish`가 그 폴더를 만든다. 318 MB, 파일 2,000여 개다. 남은 것은 그 폴더를 사용자에게 어떻게 건네느냐다.

마스터 계획은 "Setup EXE 또는 MSI"라고만 적었다. 둘 중 하나를 골라야 하고, 고르고 나면 딸려 오는 것들도 함께 정해야 한다 — 설치 범위, 설치 경로, 덮어쓰기, 제거할 때 사용자 데이터, WebView2 선행 조건.

제약이 있다.

- **WebView2 Evergreen이 없을 수 있다.** ADR-0011이 Evergreen을 기본으로 두었으므로 설치 프로그램이 그 존재를 확인하고 없으면 채워야 한다.
- **폐쇄망이 있다.** Evergreen bootstrapper는 인터넷에서 받아 오는 물건이라 폐쇄망에서는 실패한다.
- **318 MB를 그대로 건넬 수는 없다.** 압축이 필요하다.

## 결정

### Inno Setup으로 EXE 하나를 만든다

MSI로 가지 않는다. 이유는 셋이다.

**WebView2 선행 조건 때문에 MSI 하나로 끝나지 않는다.** MSI는 조건부로 다른 설치 프로그램을 부르는 일을 스스로 못 한다. WiX로 가면 결국 Burn 번들 `.exe`가 MSI를 감싸는 모양이 되고, 만들 것과 서명할 것이 둘이 된다.

**파일 2,000개의 컴포넌트를 관리해야 한다.** MSI는 파일마다 컴포넌트 GUID가 붙고 그것이 업그레이드 규칙에 얽힌다. `heat`로 훑어 만들 수 있지만, 얻는 것(복구·패치) 중 지금 필요한 것이 없다.

**서명할 파일이 하나다.** Burn 번들은 엔진과 번들을 따로 서명해야 한다 (Phase 9의 코드 서명).

MSI가 이기는 자리는 GPO나 SCCM으로 대량 배포할 때다. 그때는 `publish.py`가 만든 폴더를 WiX로 다시 싸면 된다 — **배치가 ADR-0011로 고정돼 있으므로 포장만 갈아 끼우면 된다.** 지금 MSI를 고르면 아무도 요구하지 않은 것을 위해 GUID 관리와 번들 서명을 떠안는다.

### 정한 값들

| 항목 | 값 | 왜 |
| --- | --- | --- |
| AppId | `{{4C534A54-394D-4675-A0BD-70EEB872D40B}` | 덮어쓰기 설치가 같은 앱임을 아는 근거다. 한 번 정하면 바꾸지 않는다 |
| 설치 경로 | `{autopf}\Bim4D Viewer` | 관리자로 설치하면 `Program Files`, 사용자로 설치하면 그 사용자 자리다 |
| 기본 권한 | 관리자 | 여러 사용자가 쓰는 PC가 흔하다 |
| 권한 낮추기 | `/CURRENTUSER`로 허용 | 관리자 권한이 막힌 PC에서도 깔 수 있어야 한다 |
| 무인 설치 | `/VERYSILENT /NORESTART` | Intune·SCCM이 `.exe`를 이렇게 부른다 |
| 산출물 이름 | `Bim4dViewer-Setup-<버전>.exe` | 버전이 파일 이름에 있어야 무엇을 받았는지 안다 |
| 압축 | LZMA2/max, solid | 318 MB를 한 파일로 건넨다 |
| 버전 | `apps/desktop/Directory.Build.props`의 `<Version>` 한 곳 | 셸과 설치본이 다른 버전을 말하지 않는다 |

### 덮어쓰기 설치는 제자리에서 한다

같은 AppId면 Inno가 기존 설치를 알아보고 그 자리에 덮어쓴다. 이전 버전을 먼저 제거하지 않는다. 다만 **설치 전에 실행 중인 셸을 닫게 한다.** WebView2와 Python 워커가 파일을 잡고 있으면 덮어쓰기가 실패한다.

### 제거해도 사용자 데이터는 남긴다

`%APPDATA%\Bim4dViewer`에는 설정, 최근 프로젝트 목록, 로그가 있다. 제거해도 지우지 않는다.

- 다시 깔면 최근 목록이 그대로 있는 편이 낫다
- 로그는 왜 지웠는지 물을 때 필요한 물건이다. 제거와 함께 사라지면 문제를 남긴 채 증거만 사라진다

지우고 싶은 사람을 위해 자리를 문서에 적어 둔다. 조용히 지우는 것보다 조용히 남기는 쪽이 되돌릴 수 있다.

**설치 폴더는 비운다.** WebView2가 실행 중에 `{app}\Bim4d.Desktop.exe.WebView2`에 캐시를 만들며, 설치 프로그램이 담은 것이 아니라 그대로 두면 제거 뒤에도 남는다. 브라우저 캐시는 사용자 데이터가 아니므로 제거할 때 함께 지운다. 첫 제거 시험에서 파일 22개가 남는 것을 보고 넣은 규칙이다.

### WebView2는 있으면 넘어가고 없으면 채운다

설치 중에 레지스트리에서 Evergreen Runtime을 확인한다.

```text
HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}
HKCU\SOFTWARE\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}
```

`pv` 값이 있고 `0.0.0.0`이 아니면 깔려 있는 것이다. 없으면 동봉한 `MicrosoftEdgeWebView2Setup.exe`를 조용히 실행한다.

**bootstrapper는 인터넷을 쓴다.** 폐쇄망에서는 이 단계가 실패하며, 그때는 설치를 멈추지 않고 무엇이 없는지 알린다. 폐쇄망용 Fixed Version 산출물은 ADR-0011이 정한 대로 별도이며 그쪽은 이 확인을 건너뛴다.

### 파일 연결은 하지 않는다

`.ifc`는 여러 프로그램이 함께 쓰는 확장자다. 설치가 조용히 그것을 가져가지 않는다. 셸은 `--open <경로>`를 이미 받으므로 필요해지면 그때 **선택 항목으로** 더한다.

## 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
| ---- | ---- | ---- | ------------------ |
| WiX MSI + Burn 번들 | GPO·SCCM 배포, 복구, 패치 | 만들 것과 서명할 것이 둘. 파일 2,000개의 컴포넌트 GUID 관리 | 지금 아무도 요구하지 않는다. 배치가 고정돼 있어 나중에 포장만 갈아 끼울 수 있다 |
| 압축한 ZIP만 건넨다 | 만들 것이 없다 | 시작 메뉴도 제거도 WebView2 확인도 없다. 사용자가 손으로 푼다 | 폐쇄망 임시 배포용으로는 쓸 수 있으나 제품의 기본 경로가 될 수 없다 |
| MSIX | Windows 표준 포장, 자동 업데이트 | 서명이 필수고, 컨테이너가 자식 프로세스(Python 워커)와 파일 접근을 제약한다 | ADR-0009가 자식 프로세스를 전제한다. 위험을 지금 떠안을 이유가 없다 |
| 제거할 때 사용자 데이터도 지운다 | 흔적이 남지 않는다 | 다시 깔면 최근 목록이 비고, 문제를 남긴 채 로그만 사라진다 | 조용히 지우는 것은 되돌릴 수 없다 |
| 설치 프로그램이 Fixed Version WebView2를 함께 담는다 | 폐쇄망에서도 한 번에 끝난다 | 모든 사용자에게 180 MB를 물린다 | ADR-0011이 별도 산출물로 정했다 |

## 결과

**가능해지는 것**

- 받는 사람은 `.exe` 하나를 두 번 누르면 된다. .NET도 Python도 WebView2도 따로 깔지 않는다
- `/VERYSILENT`로 무인 배포가 된다
- 덮어쓰기 설치가 제자리에서 되고, 제거해도 설정과 기록이 남는다

**포기하는 것**

- GPO 소프트웨어 설치로는 배포하지 못한다. 그 요구가 오면 MSI를 따로 만든다
- MSI의 복구와 패치가 없다. 고치는 방법은 다시 설치하는 것이다

**영향 받는 경로와 계약**

| 무엇 | 어떻게 |
| --- | --- |
| `apps/desktop/installer/` | Inno Setup 스크립트가 새로 생긴다 |
| `apps/desktop/tools/publish.py` | 만든 폴더를 설치 프로그램이 그대로 싼다. 바뀌지 않는다 |
| `apps/desktop/Directory.Build.props` | 버전 한 곳. 셸과 설치본이 함께 읽는다 |
| `%APPDATA%\Bim4dViewer` | 제거해도 남는 자리임이 계약이 된다 |

## 후속 작업

- [ ] Inno Setup 스크립트를 두고 `pnpm shell:installer`로 만든다
- [ ] CI에 Inno Setup이 있는지 확인하고, 없으면 설치 단계를 더한다
- [ ] 설치 → 실행 → 덮어쓰기 설치 → 제거를 실제로 해 보고 결과를 worklog에 적는다
- [ ] 코드 서명 자리를 스크립트에 뚫어 둔다 (`SignTool`). 인증서는 사용자 몫이다
- [ ] 폐쇄망용 Fixed Version 산출물의 만들기 절차 (ADR-0011)
