# performance

성능 측정. 마스터 계획 10.3절에 따라 표준 모델 fixture가 선정된 뒤 수치 기준을 정한다. 임의의 목표 수치를 먼저 고정하지 않는다.

여기 적는 것은 **잰 값이지 목표가 아니다.** 나중에 느려졌을 때 견줄 자리를 만들어 두는 것이다.

## 어떻게 재나

```powershell
# 저장소 뿌리에서 설치본을 먼저 만든다
pnpm build
pnpm shell:publish

# 그다음 창을 띄워 잰다
tests\performance\Measure-ModelOpen.ps1 -Ifc C:\models\a.ifc
```

`Measure-ModelOpen.ps1`이 하는 일은 셋이다.

1. 설치본 셸을 `--open`으로 띄운다
2. 3초마다 **셸의 프로세스 트리**의 작업 집합을 잰다 — 이름으로 세면 이 PC의 다른 앱이 띄운 `msedgewebview2`까지 합산된다
3. 셸이 남긴 기록에서 `모델을 넘겼다`와 `모델을 열었다`의 시각 차를 낸다

창을 띄워야 하는 측정이라 CI에 넣지 않는다. 사람이 필요할 때 돌린다.

### 2026-09-07 — 소형 fixture (대조군)

같은 PC, 같은 설치본으로 저장소의 fixture를 열었다. 셸과 WebView2 자체가 쓰는 몫을 알기 위한 기준선이다.

| 항목        | 값                                       |
| ----------- | ---------------------------------------- |
| 파일        | `three-elements-ifc4.ifc`, 13 KB, 부재 3 |
| 여는 시간   | 0.2초                                    |
| 안정 메모리 | 528 MB                                   |

**둘을 견주면** 128 MB 모델의 안정 865 MB 중 셸과 브라우저가 528 MB이고, **모델 자체가 차지하는 것은 약 340 MB**다. 정점 1,699 MB 중에서도 모델 몫은 약 1,170 MB다.

**읽는 법**

- 여는 데 10초, 안정 상태 865 MB다. 16 GB PC에서는 여유롭다
- 빈 셸이 이미 528 MB를 쓴다. WebView2를 띄우는 값이며 모델과 무관하게 든다
- 정점 1.7 GB는 8 GB PC에서 다른 프로그램과 함께 쓰면 빠듯할 수 있다. 변환이 끝나면 내려가므로 정점만 넘기면 된다
- **표본이 하나다.** 뷰어 성능은 파일 크기보다 부재 수에 민감하다. 부재 10만 개짜리 모델은 파일이 작아도 다르게 굴 수 있다
- 회전할 때의 FPS와 선택 반응은 재지 않았다. 창을 자동으로 조작할 방법이 없어 사람이 만져 봐야 한다
